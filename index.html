    1. What a script is

    A script is a text file of shell commands. The shebang line tells Linux which interpreter to use.

    

    

    Hello from ./hi.sh
    

    Put personal tools in ~/bin and add it to PATH in ~/.bashrc: export PATH="$HOME/bin:$PATH".
    
Bash-only tip: prefer #!/usr/bin/env bash over hard-coding /bin/bash when the path varies.

    Warning
    Practice in a disposable directory or VM. Never test destructive scripts on important data.

    14. Robust scripting
    

    • set -e — exit on failing command (with nuances in if/and-or lists).
    • set -u — error on unset variables.
    • set -o pipefail — pipeline fails if any stage fails.
    Warning
    set -e is not magic—commands in if cmd; then are exempt. Still check critical commands explicitly.
    Tip
    Install shellcheck and run it on every script: shellcheck myscript.sh.

    32. Style & best practices
    


      

    • Name scripts verb-noun.sh; functions snake_case.
      • 

    • Put logic in functions; call main "$@" at the bottom.
      • 

    • Comments explain why, not what the syntax already says.
      • 

    • Prefer Bash extensions only when you declare #!/usr/bin/env bash.
      • 

    • Run shellcheck in CI.
      •

    33. Cheat sheet
    


    

    TopicSyntax
    


    Shebang#!/usr/bin/env bash
    

    Strict modeset -euo pipefail
    

    Test[[ -f $f ]] [[ $a == b ]]
    

    Defaults${x:-default} ${x:?err}
    

    Arraysa=(..) "${a[@]}"
    

    Redirect> >> 2> |& tee
    

    Special$# $@ $? $0 $$ $!
    

    Traptrap cleanup EXIT
